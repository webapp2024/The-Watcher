# The Watcher - ระบบติดตามแผนจัดซื้อ

Frontend: GitHub Pages · Backend: Google Apps Script (JSON API) · DB: Google Sheets

ใช้กำกับติดตามการจัดซื้อให้อยู่ในกรอบแผนประจำปีงบประมาณ ตั้งแต่บันทึกแผนที่ได้รับอนุมัติ
ขออนุมัติซื้อ (ตัดยอดจากแผนอัตโนมัติ) ไปจนถึงดูผลตามแผนและออกรายงาน

---

| หน้า | ทำอะไร |
|---|---|
| **หน้าหลัก** | แผนประจำปีงบประมาณ พ.ศ. .... (เปลี่ยนปีงบได้) · สรุปวงเงินตามแผน / ขอซื้อไปแล้ว / คงเหลือ แยกตามประเภท |
| **ประเภทแผน** | 17 ประเภทเริ่มต้น ดูยอดรายประเภท เจาะเข้าไปดูรายการในแผน · เพิ่ม/แก้ไข/ลบ/จัดลำดับได้ |
| **แผนประจำปี** | ใส่รายการที่ได้รับอนุมัติตามแผน: ประเภท · รหัสรายการ · ชื่อ · หน่วยนับ · จำนวน · วงเงิน |

| **ผลตามแผน** | 3 ส่วน: ① แผน ② ผลตามแผน (จำนวน/วงเงินที่ขอซื้อทั้งหมด) ③ คงเหลือ |

### ทะเบียนรายการ (บันทึกครั้งเดียว ใช้ซ้ำได้)
รหัสรายการ / ชื่อ / หน่วยนับ จะถูกเก็บเข้าทะเบียนกลางตอนบันทึกครั้งแรก
ครั้งต่อไปหรือในหน้าอื่น ๆ แค่ใส่ **รหัสรายการ** แล้วกดออกจากช่อง (หรือ Enter)
ระบบจะดึงชื่อและหน่วยนับขึ้นมาให้อัตโนมัติ — กดปุ่มแว่นขยายเพื่อค้นหาจากชื่อก็ได้

### รายงานขออนุมัติซื้อ (เลือกช่วงวันที่)
เมนู **รายงาน > รายงานขออนุมัติซื้อ** ตอบคำถามแบบ "วันที่ 18/9/69 แผนยาขอซื้อไปกี่รายการ เป็นเงินเท่าไร"

- ปุ่มลัด: วันนี้ · เมื่อวาน · 7 วันล่าสุด · เดือนนี้ · ทั้งปีงบ — หรือเลือกช่วงวันเองก็ได้
- แสดง **สรุปตามประเภทแผน** (จำนวนรายการ + รวมเป็นเงิน) แล้วตามด้วยรายละเอียดทุกรายการ
- กด **พิมพ์ / PDF** ได้เอกสาร A4 แนวนอน: หัวกระดาษชื่อหน่วยงาน + โลโก้ · ช่วงวันที่ ·
  ตารางสรุป · จำนวนเงินเป็นตัวอักษร · ตารางรายละเอียด · ช่องลงนาม ผู้จัดทำ/ผู้ตรวจสอบ/ผู้อนุมัติ
- ส่งออก Excel ได้ตามช่วงวันเดียวกัน (ชื่อไฟล์ติดวันที่ให้อัตโนมัติ)
- ระบุช่วงวันเมื่อไหร่ ระบบจะกรองด้วยวันที่ล้วน ๆ ไม่ผูกกับปีงบ (กันกรณีเลือกวันคาบเกี่ยวปีงบแล้วได้ผลว่าง)

### การกันซื้อเกินแผน
- ขออนุมัติซื้อได้เฉพาะรหัสที่มีอยู่ในแผนของ **ประเภทและปีงบเดียวกัน**
- ถ้าจำนวนหรือวงเงินเกินยอดคงเหลือ ระบบจะเตือนตั้งแต่ตอนกรอก และไม่ยอมบันทึก
- ผู้ดูแลระบบยืนยันบันทึกทับได้ รายการนั้นจะถูกทำเครื่องหมาย "เกินแผน" ในรายงาน
- ปิดการกันทั้งระบบได้ที่ ตั้งค่า > ข้อมูลโรงพยาบาล
- ลบใบขออนุมัติซื้อ = คืนยอดกลับเข้าแผนทันที

## ติดตั้ง

### A. Backend (Apps Script + Sheet)
1. สร้าง Google Sheet > Extensions > Apps Script
2. วางเนื้อหา `Code.gs` ทั้งหมด บันทึก
3. รันฟังก์ชัน `setup` หนึ่งครั้ง (อนุญาตสิทธิ์ Drive/Sheets)
4. Deploy > New deployment > Web app > Execute as **Me**, Who has access **Anyone** > คัดลอก URL `/exec`
   - แก้โค้ดภายหลังต้อง Deploy > Manage deployments > New version ทุกครั้ง

### B. Frontend (GitHub Pages)
1. แก้ `js/api.js` ใส่ค่า `API_URL` เป็น URL `/exec`
2. push โฟลเดอร์นี้ขึ้น GitHub repo
3. Settings > Pages > เลือก branch `main` / root > บันทึก

### C. เข้าใช้ครั้งแรก
- `admin` / `admin1234` (เปลี่ยนรหัสได้ที่ ตั้งค่า > บัญชีผู้ใช้)

## บทบาทผู้ใช้

| บทบาท | สิทธิ์ |
|---|---|
| **ผู้ดูแลระบบ (admin)** | ใช้ได้ทุกเมนู · จัดการผู้ใช้ เพิ่ม/แก้ไข/ลบ/รีเซ็ตรหัสผ่าน |
| **ผู้ใช้งาน (user)** | เพิ่มข้อมูลได้เฉพาะหน้าขออนุมัติซื้อ · ดูผลตามแผนและแดชบอร์ดได้ |

เมนูล่าง/แถบข้างจะถูกสร้างตามสิทธิ์ ผู้ใช้ที่ไม่มีสิทธิ์จะไม่เห็นเมนูนั้น และฝั่ง backend
ตรวจสิทธิ์ซ้ำทุกคำขอ (การซ่อนเมนูอย่างเดียวไม่ถือเป็นการป้องกัน)

## ปีงบประมาณ
- เก็บเป็น **พ.ศ.** ปีงบประมาณไทยเริ่ม 1 ต.ค. (ต.ค. 2568 = ปีงบ 2569)
- ปุ่ม "ปีงบ ####" ที่มุมขวาบนของทุกหน้าใช้สลับปีที่กำลังดู/บันทึก
  - ผู้ดูแลระบบ: เปลี่ยนแล้วบันทึกเป็นค่าเริ่มต้นของระบบด้วย และเพิ่มปีใหม่ได้
  - ผู้ใช้งาน: สลับดูได้เฉพาะในเซสชันของตัวเอง
- ข้อมูลแผนและใบขออนุมัติซื้อแยกกันตามปีงบอย่างสมบูรณ์

## ชีตใน Google Sheet
| ชีต | เก็บอะไร |
|---|---|
| `Config` | ชื่อ/โลโก้โรงพยาบาล ปีงบเริ่มต้น ตัวเลือกระบบ |
| `Categories` | ประเภทแผน 17 ประเภท (ไอคอน สี ลำดับ) |
| `Units` | หน่วยนับ |
| `Products` | ทะเบียนรายการ: รหัส / ชื่อ / หน่วยนับ |
| `Plans` | รายการในแผนประจำปี (จำนวน + วงเงินที่ได้รับอนุมัติ) |
| `Purchases` | ใบขออนุมัติซื้อ |
| `Users` `Sessions` `Errors` | ผู้ใช้ เซสชัน และ log ข้อผิดพลาด |

> ชีตของระบบเดิม (`Locations` `Drugs` `Items` `Transactions`) จะไม่ถูกแตะต้อง
> `setup()` สร้างเฉพาะชีตที่ยังไม่มี และเติมเฉพาะคีย์ที่ขาดใน `Config`

## ความปลอดภัย / CORS
- โค้ดฝั่ง GitHub เป็น public อย่าใส่ secret ในฝั่งนี้
- API ใช้ POST `Content-Type: text/plain` และไม่ใส่ custom header เพื่อเลี่ยง CORS preflight
- endpoint เปิด Anyone ระบบจึง validate session token ทุกคำขอ (หมดอายุใน 8 ชม.)
